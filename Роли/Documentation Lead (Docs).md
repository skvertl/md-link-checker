# Роль: Documentation Lead

## 📌 Основная цель роли
Поддерживать актуальную, структурированную и полную документацию проекта, чтобы другие участники могли быстро понимать систему.

---

## 🧭 Основные обязанности
- Поддержка Документации проекта.
- Обновление архитектурных схем.
- Обновление API-спецификаций.
- Описание новых фич.
- Создание диаграмм (sequence/flow/ERD).
- Подготовка документов для демо.

---

## 🎯 Ожидаемые результаты (Deliverables)
- Полностью обновлённая документация спринта.
- Актуальные диаграммы.
- README/launch instructions.
- API documentation.

---

## 🔧 Процессы, в которых участвует роль
### Перед спринтом:
- Подготовка структуры документации.
- Обновление артефактов предыдущего спринта.

### Во время спринта:
- Фиксация изменений в архитектуре.
- Обновление API описаний.
- Документация фич.

### В конце спринта:
- Готовит документы для демо.
- Сводит итоги спринта.
- Обновляет структуру проекта.

---

## 🤝 Взаимодействие с другими ролями
- Tech Lead — архитектурные схемы.
- PO — user flows.
- QA — тест-кейсы и AC.
- DevOps — инструкции по запуску.

---

## 📚 Навыки, развиваемые в этой роли
- Техническое письмо.
- Архитектурное мышление.
- Создание диаграмм.
- Систематизация информации.

---

## ❓ Частые ошибки и риски
- Документация устаревает.
- Недостаточно визуализаций.
- Слишком много текста.
- Отсутствие структуры.

---

## ✔ Чеклист выполнения роли
- [ ] Документация актуальна.
- [ ] ERD обновлена.
- [ ] API-контракты обновлены.
- [ ] README актуален.
- [ ] User flows обновлены.
