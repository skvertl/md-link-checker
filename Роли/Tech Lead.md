# Роль: Tech Lead

## 📌 Основная цель роли
Определять техническое направление команды и обеспечивать качество архитектуры, кода и инженерных решений.

---

## 🧭 Основные обязанности
- Определение архитектуры бэкенда и фронтенда.
- Разработка ERD и API схем.
- Создание технических стандартов.
- Проведение code review ключевых PR.
- Поддержка и менторство разработчиков.
- Участие в технических обсуждениях и принятии решений.

---

## 🎯 Ожидаемые результаты (Deliverables)
- Чёткая архитектура модуля/фичи.
- Обновлённая ERD/диаграммы.
- Созданные технические гайды.
- Принятые технические решения (ADR).
- Высокое качество ревью.

---

## 🔧 Процессы, в которых участвует роль
### Перед спринтом:
- Анализ требований.
- Планирование архитектуры.
- Определение технических ограничений.

### Во время спринта:
- Ревью сложных PR.
- Менторство команды.
- Помощь в дебаге.
- Поддержка QA по API.

### В конце спринта:
- Технические итоги.
- Обновление документации.
- Анализ качества кода.

---

## 🤝 Взаимодействие с другими ролями
- PO — проверка реализуемости требований.
- DevOps — инфраструктура.
- QA — тестирование API.
- Docs — архитектурные артефакты.
- TL — синхронизация по процессам.

---

## 📚 Навыки, развиваемые в этой роли
- Архитектура ПО.
- Code review.
- Менторство.
- Работа с требованиями.
- Системное мышление.

---

## ❓ Частые ошибки и риски
- Уход в микроменеджмент.
- Придумывание “слишком сложной архитектуры”.
- Недостаток документации.
- Задержки PR.

---

## ✔ Чеклист выполнения роли
- [ ] Архитектура спринта определена.
- [ ] ERD обновлена.
- [ ] Все сложные PR проверены.
- [ ] Технические риски закрыты.
- [ ] ADR оформлены.

---

## 📝 Примечания
Tech Lead не должен делать “весь сложный код сам”.
