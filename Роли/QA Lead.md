# Роль: QA Lead

## 📌 Основная цель роли
Обеспечить стабильное качество продукта и минимизировать баги с помощью тестирования, планирования и проверки DoD.

---

## 🧭 Основные обязанности
- Написание тест-кейсов для фич.
- Ручное тестирование.
- API тесты (через Postman/Bruno).
- UI тесты.
- Проверка выполнения acceptance criteria.
- Регресс в конце спринта.

---

## 🎯 Ожидаемые результаты (Deliverables)
- Тест-план спринта.
- Набор тест-кейсов.
- Список багов.
- Подтверждение DoD по фичам.
- Отчёт о регрессионном тестировании.

---

## 🔧 Процессы, в которых участвует роль
### Перед спринтом:
- Анализ требований.
- Подготовка тест-кейсов.

### Во время спринта:
- Проверка фич.
- Создание баг-репортов.
- API/UI тестирование.

### В конце спринта:
- Регресс.
- Отчёт о качестве.
- Проверка соответствия AC.

---

## 🤝 Взаимодействие с другими ролями
- PO — AC и качество фич.
- TL — блокеры.
- Tech Lead — API корректность.
- Docs — документация по API.

---

## 📚 Навыки, развиваемые в этой роли
- Тест-дизайн.
- Анализ требований.
- API тестирование.
- Коммуникация.
- Bug reporting.

---

## ❓ Частые ошибки и риски
- Тестирование “в последний день”.
- Слишком общие тест-кейсы.
- Игнорирование багов.
- Отсутствие регресса.

---

## ✔ Чеклист выполнения роли
- [ ] Тест-план готов.
- [ ] Тест-кейсы написаны.
- [ ] Все фичи проверены.
- [ ] Баги заведены.
- [ ] Регресс проведён.

---

## 📝 Примечания
QA Lead не должен тестировать всё сам — он организует процесс.
