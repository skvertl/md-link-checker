## Краткое содержание

Этот документ предоставляет пошаговое руководство по установке и запуску проекта Python-TypeScript Wiki Frontend.
Описаны два рабочих сценария: запуск полного стека через `python-typescript-wiki` (`docker compose`) и запуск только фронтенда из `python-typescript-wiki-frontend` через локальный `npm`.
Все команды и требования в документе привязаны к фактическим файлам репозиториев (`package.json`, `Dockerfile`, `docker-compose.yaml`).

## Запуск через Docker Compose в монорепозитории

Этот сценарий относится к репозиторию `python-typescript-wiki`, а не к `python-typescript-wiki-frontend`.

### Инициализация submodules

```bash
cd ../python-typescript-wiki
git submodule update --init --recursive
```

### Запуск сервисов

```bash
cd ../python-typescript-wiki
docker compose up -d
```

Альтернатива, которая есть в монорепозитории:

```bash
cd ../python-typescript-wiki
chmod +x start-services.sh
./start-services.sh
```

### Сервисы и порты (по `python-typescript-wiki/docker-compose.yaml`)

| Сервис | Порты |
|--------|-------|
| `frontend` | `3000:5173` |
| `api` | `8000:8000` |
| `postgres` | `5432:5432` |
| `pgadmin` | `5050:80` |
| `proxy` | `80:80`, `443:443` |

### Управление

```bash
cd ../python-typescript-wiki
docker compose down
docker compose logs -f frontend
docker compose restart frontend
```

## Локальная разработка без Docker

Для работы только с фронтендом без контейнеров:

### Установка зависимостей

```bash
cd python-typescript-wiki-frontend

# Установка всех зависимостей
npm install
```

### Настройка окружения для локальной разработки

**Примечание:** Для локальной разработки без Docker создайте `.env` файл в корне фронтенда.

```bash
cd python-typescript-wiki-frontend
cp .env.example .env
```

### Переменные окружения

Переменные, которые реально используются в коде фронтенда:

| Переменная | Где используется | Обязательность |
|------------|------------------|----------------|
| `VITE_APP_ENV` | `src/shared/lib/environment.ts` | Обязательна для явного выбора режима (`local`/`development`/`production`) |
| `VITE_API_BASE_URL` | `src/shared/lib/environment.ts`, `src/shared/lib/fetch-mutator.ts` | Обязательна для real API режима |
| `VITE_SSO_APP_ID` | `src/shared/lib/environment.ts`, `src/pages/auth/ui/AuthPage.tsx` | Обязательна для работы кнопки авторизации |
| `VITE_BYPASS_AUTH` | `src/shared/lib/environment.ts`, `src/shared/lib/auth-utils.ts` | Опциональна, только для обхода route guard в разработке |
| `TEST_SSO_APP_ID` | `e2e/auth-button.spec.ts` | Обязательна для `npm run tests:e2e` |

Для режима чтения mock-данных достаточно `VITE_APP_ENV=local`.

### Сопоставление переменных: `.env.example` / `src/env.d.ts` / runtime-код

**Легенда местоположения:**
- **E** — присутствует в `.env.example`
- **D** — объявлена в `src/env.d.ts`
- **K** — используется в коде

| Переменная | Значение по умолчанию | Где | Описание |
|------------|---------------------|-----|----------|
| `VITE_API_BASE_URL` | `http://training.wiki:8000` | E✅ D✅ K✅ | Базовый URL API |
| `VITE_SSO_APP_ID` | пусто | E✅ D❌ K✅ | ID приложения для SSO |
| `VITE_APP_ENV` | `development` (в `.env.example`), fallback `local` | E✅ D✅ K✅ | Окружение: `local`/`development`/`production` |
| `VITE_APP_NAME` | `wiki-frontend` | E✅ D❌ K❌ | Есть только в `.env.example` *(не используется)* |
| `VITE_BRAND_NAME` | - | E❌ D✅ K❌ | Есть только в `src/env.d.ts` *(не используется)* |
| `VITE_APP_DEBUG` | `true` | E✅ D✅ K❌ | Режим отладки *(не используется в коде)* |
| `VITE_API_TIMEOUT` | `30000` | E✅ D✅ K❌ | Таймаут API запросов *(не используется в коде)* |
| `VITE_QUERY_STALE_TIME` | `300000` | E✅ D✅ K❌ | Время устаревания кэша *(не используется, в коде 60000)* |
| `VITE_QUERY_CACHE_TIME` | `600000` | E✅ D✅ K❌ | Время жизни кэша *(не используется)* |
| `VITE_AUTH_TOKEN_MAX_AGE_MS` | `3600000` | E✅ D❌ K❌ | Переменная присутствует, но в коде не читается |
| `DOCKER_FRONTEND_PORT` | `3000` | E✅ D✅ K❌ | Переменная присутствует, но в коде не читается |
| `DOCKER_FRONTEND_HOST` | `0.0.0.0` | E✅ D✅ K❌ | Переменная присутствует, но в коде не читается |
| `VITE_ALLOWED_ORIGINS` | `http://localhost:3000,http://localhost:8000` | E✅ D✅ K❌ | Переменная присутствует, но в коде не читается |
| `VITE_APP_DOMAIN` | `https://training.wiki` | E✅ D❌ K❌ | Переменная присутствует, но в коде не читается |
| `VITE_BYPASS_AUTH` | - | E❌ D✅ K✅ | Обход авторизации, срабатывает только при значении `true` |
| `TEST_SSO_APP_ID` | пусто | E✅ D❌ K✅ | ID для E2E теста `auth-button.spec.ts` |

### Пример .env файла

```bash
# Real API режим
VITE_APP_ENV=development
VITE_API_BASE_URL=http://training.wiki:8000
VITE_SSO_APP_ID=your-app-id

# Local/mock режим
# VITE_APP_ENV=local

# Опционально: обход проверки авторизации в route guard
# VITE_BYPASS_AUTH=true

# Для E2E:
# TEST_SSO_APP_ID=your-test-app-id
```

## Запуск проекта (локально, без Docker)

### Режим разработки

```bash
# Запуск dev сервера
npm run dev
```

Dev сервер запускается на всех сетевых интерфейсах (`--host 0.0.0.0`). В E2E-конфигурации в качестве порта по умолчанию используется `5173`.

### Production сборка

```bash
# Сборка для продакшена
npm run build
```

Результат сохраняется в папке `dist/`.

### Предпросмотр production сборки

```bash
# Предпросмотр собранного приложения
npm run preview
```

### Запуск E2E тестов

```bash
# Запуск E2E тестов (требуется TEST_SSO_APP_ID)
export TEST_SSO_APP_ID=your-test-app-id
npm run tests:e2e
```

`npm run tests:e2e` использует `node --env-file=.env`, поэтому переменные можно задавать как через экспорт в shell, так и через `.env`.

**Переменные окружения для E2E тестов:**

| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `TEST_SSO_APP_ID` | - | ID приложения SSO для тестов (обязателен) |
| `PORT` | `5173` | Порт приложения |
| `E2E_BASE_URL` | `http://training.wiki:PORT` | Базовый URL для тестов |
| `CI` | `false` (если не задана) | Включает CI-режим Playwright (retries/reporter/workers) |

**Пример:**
```bash
export TEST_SSO_APP_ID=test-app-123
export E2E_BASE_URL=http://localhost:5173
npm run tests:e2e
```

## Генерация API клиента

### Первая генерация

```bash
# Генерация API клиента из OpenAPI спецификации
npm run api:generate
```

Это создаст TypeScript клиента в `src/shared/orval-api/withToken/`.

### Когда нужно перегенерировать

- После изменений в API бэкенда
- После обновления mock данных (`mock/mock.api.json`)
- После добавления новых эндпоинтов

### Что генерирует Orval

- TypeScript типы для API запросов/ответов
- React Query хуки (`useQuery`, `useMutation`)
- Zod схемы для валидации

**Подробнее:** [API клиент](./API%20клиент.md)

## Работа в разных режимах

`VITE_APP_ENV` используется в `src/shared/lib/environment.ts` и влияет на функцию `isLocalRun()`.

### Local режим (`VITE_APP_ENV=local`)

```bash
# .env
VITE_APP_ENV=local
```

**Особенности:**
- `useSpaces` и `useSpace` читают данные из `src/shared/mock/spaceMocks.ts`
- Проверка авторизации может быть отключена через `VITE_BYPASS_AUTH=true`
- Создание пространства (`createSpace`) всё равно вызывает API `POST /api/v1/spaces`

### Non-local режим (`VITE_APP_ENV=development` или `production`)

**Особенности:**
- `useSpaces` и `useSpace` вызывают backend через `fetchWithToken`
- Используется `VITE_API_BASE_URL` для построения URL запросов
- В коде нет отдельной runtime-логики, различающей `development` и `production`

## Troubleshooting

### `npm run tests:e2e` падает из-за отсутствия переменной

**Проблема:**
```
Error: SSO_APP_ID environment variable is required for this test
```

В `e2e/auth-button.spec.ts` реально читается `process.env.TEST_SSO_APP_ID`, при этом текст ошибки использует название `SSO_APP_ID`.

**Решение:**
```bash
export TEST_SSO_APP_ID=your-test-app-id
npm run tests:e2e
```

### В `local` режиме не работает создание пространства

**Проблема:** при `VITE_APP_ENV=local` список пространств открывается, но создание нового пространства падает.

**Причина в коде:** `useSpaces`/`useSpace` используют mock данные только для чтения, а `createSpace` всегда вызывает backend `POST /api/v1/spaces`.

**Решение:** для создания пространства нужен доступный backend и корректный `VITE_API_BASE_URL`.

### Ошибка генерации API клиента

**Проблема:**
```
Error: Cannot find module './mock/mock.api.json'
```

**Решение:**
1. Убедитесь, что файл `mock/mock.api.json` существует
2. Проверьте путь в `orval.config.ts`
3. Повторите `npm run api:generate`

### Ошибка TypeScript импорта по alias `@/...`

**Проблема:**
```
error TS2307: Cannot find module '@/...'
```

**Решение:**
1. Проверьте, что aliases совпадают в `tsconfig.json` и `vite.config.ts`.
2. Проверьте, что импортируемый путь реально существует в `src/`.
