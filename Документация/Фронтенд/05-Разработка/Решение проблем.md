## Переменные окружения

### Проблема: Переменные окружения не определены

**Симптомы:**
- TypeScript/`npm run build` падает с ошибкой `TS2367: ... types 'boolean | undefined' and 'string' have no overlap` в `src/shared/lib/environment.ts`
- Значение переменной равно `undefined`

**Причина:**
Обычно это один из следующих случаев:
- Файл `.env` не создан / не заполнен
- Переменная используется в коде, но не объявлена в `src/env.d.ts`
- Тип переменной в `src/env.d.ts` не совпадает с тем, как она используется в коде (например, `VITE_BYPASS_AUTH`)

**Решение:**

1. Создайте файл `.env` из шаблона:
```bash
cp .env.example .env
```

2. Убедитесь, что все переменные объявлены в `.env`:
```bash
# Основные переменные
VITE_API_BASE_URL=http://training.wiki:8000
VITE_SSO_APP_ID=your-sso-app-id
VITE_APP_ENV=local

# Опциональные переменные
VITE_BYPASS_AUTH=false
VITE_APP_DEBUG=true
```

3. Проверьте декларации в `src/env.d.ts` и приведите типы к фактическому использованию в коде:
```typescript
interface ImportMetaEnv {
  readonly VITE_SSO_APP_ID: string;
  readonly VITE_BYPASS_AUTH?: string;
}
```
Текущее состояние репозитория: `VITE_SSO_APP_ID` в `src/env.d.ts` отсутствует, а `VITE_BYPASS_AUTH` объявлен как `boolean`, при том что в коде сравнивается со строкой `'true'`.

4. Перезапустите dev сервер:
```bash
npm run dev
```

### Проблема: Переменная окружения равна `undefined` в коде

**Симптомы:**
- `APP_ID` или `BASE_URL` равны `undefined`
- API запросы идут на неправильный URL

**Причина:**
Переменная окружения не начинается с `VITE_` или не объявлена в `.env`

**Решение:**

1. Убедитесь, что переменная начинается с `VITE_`:
```bash
# ❌ Неправильно
API_BASE_URL=http://localhost:8000

# ✅ Правильно
VITE_API_BASE_URL=http://localhost:8000
```

2. Проверьте объявление в коде (`src/shared/lib/environment.ts`):
```typescript
export const APP_ID = import.meta.env.VITE_SSO_APP_ID;
export const BASE_URL = import.meta.env.VITE_API_BASE_URL;
```

### Проблема: Mock режим не работает

**Симптомы:**
- Приложение всё равно делает запросы к API
- Mock данные не загружаются

**Причина:**
Переменная `VITE_APP_ENV` не установлена в `local`

**Решение:**

В `.env` файле:
```bash
# Mock режим (нет бэкенда)
VITE_APP_ENV=local

# Real API режим
VITE_APP_ENV=development
```

Проверьте логику в `src/shared/lib/environment.ts`:
```typescript
const APP_ENV = import.meta.env.VITE_APP_ENV || 'local';

export const isLocalRun = () => APP_ENV === 'local';
```

## Авторизация и токены

### Проблема: Ошибка авторизации (код ошибки на `/token`)

**Симптомы:**
- Страница `/token` показывает ошибку `SESSION_MISSING`, `OAUTH_CODE_INVALID` или `SESSION_EXPIRED`
- Пользователь не может войти в систему

**Причина:**
Токен не передаётся в URL или истёк срок действия токена

**Решение:**

1. Проверьте URL на странице авторизации:
```typescript
// src/pages/auth/ui/AuthPage.tsx
function getSsoLoginUrl(): string {
  return `https://sso.oauth.name/access/?grant=${APP_ID}`;
}
```

2. Убедитесь, что `APP_ID` определён:
```typescript
// src/shared/lib/environment.ts
export const APP_ID = import.meta.env.VITE_SSO_APP_ID;
```

3. Для локальной разработки используйте обход авторизации:
```bash
VITE_BYPASS_AUTH=true
```

**Код ошибки:**

В `src/pages/token/ui/TokenPage.tsx`:
```typescript
const errorCode = isErrorResponse(error)
  ? error.message
  : ErrorCodeType.INTERNAL_ERROR;

// Возможные ошибки:
// - SESSION_MISSING
// - OAUTH_CODE_INVALID
// - SESSION_EXPIRED
// - INTERNAL_ERROR
```

### Проблема: Токен не парсится корректно

**Симптомы:**
- Токен с двоеточием (`:`) обрезается
- API возвращает ошибку `OAUTH_CODE_INVALID`

**Причина:**
Бэкенд ожидает только часть токена после двоеточия

**Решение:**

Проверьте код в `src/pages/token/ui/TokenPage.tsx`:
```typescript
const rawToken = new URLSearchParams(window.location.search).get('token');

if (!rawToken) {
  const missingTokenError: ErrorResponseType = {
    status: 'error',
    message: ErrorCodeType.SESSION_MISSING,
    timestamp: new Date().toISOString(),
  };
  return <ErrorState error={missingTokenError} />;
}

// Бэкенду нужна только часть после двоеточия
const token = rawToken.includes(':')
  ? rawToken.split(':').slice(1).join(':') // Обработка нескольких двоеточий
  : rawToken;
```

### Проблема: ErrorState показывает "INTERNAL_ERROR"

**Симптомы:**
- Страница показывает общее сообщение об ошибке
- Не понятна причина проблемы

**Причина:**
Ответ от API не соответствует ожидаемому формату

**Решение:**

Проверьте функцию `isErrorResponse`:
```typescript
function isErrorResponse(error: unknown): error is ErrorResponseType {
  return (
    typeof error === 'object' &&
    error !== null &&
    'message' in error &&
    typeof (error as ErrorResponseType).message === 'string'
  );
}
```

Ожидаемый формат ошибки:
```typescript
interface ErrorResponseType {
  status?: 'error';
  message: ErrorCodeType;
  timestamp: string;
}

type ErrorCodeType =
  | 'VALIDATION_ERROR'
  | 'OAUTH_CODE_INVALID'
  | 'OAUTH_STATE_INVALID'
  | 'SESSION_MISSING'
  | 'SESSION_EXPIRED'
  | 'RATE_LIMIT_EXCEEDED'
  | 'INTERNAL_ERROR';
```

## API клиент и ошибки запросов

### Проблема: API запросы не работают

**Симптомы:**
- Запросы падают с ошибкой `Network Error`
- В консоли: `Failed to fetch`

**Причина:**
- Неверный `VITE_API_BASE_URL`
- Бэкенд не запущен
- CORS ошибка

**Решение:**

1. Проверьте `VITE_API_BASE_URL`:
```bash
# Для локальной разработки
VITE_API_BASE_URL=http://localhost:8000

# Для работы в контейнерах
VITE_API_BASE_URL=http://training.wiki:8000
```

2. Проверьте, что бэкенд запущен:
```bash
# Проверка с curl
curl http://localhost:8000/health/db
```

3. Для локальной разработки используйте mock режим:
```bash
VITE_APP_ENV=local
```

### Проблема: Ошибка "Cannot find module '@/...'"

**Симптомы:**
- TypeScript показывает ошибку `TS2307: Cannot find module '@/...'`
- Билд падает с ошибкой импорта

**Причина:**
Алиасы путей не настроены в `tsconfig.json`

**Решение:**

Проверьте `tsconfig.json`:
```json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["./src/*"],
      "@/app/*": ["./src/app/*"],
      "@/pages/*": ["./src/pages/*"],
      "@/widgets/*": ["./src/widgets/*"],
      "@/features/*": ["./src/features/*"],
      "@/entities/*": ["./src/entities/*"],
      "@/shared/*": ["./src/shared/*"]
    }
  }
}
```

Проверьте `vite.config.ts`:
```typescript
import path from 'path';

export default defineConfig({
  resolve: {
    alias: {
      '@': path.resolve(__dirname, './src'),
    },
  },
  // ... остальная конфигурация
});
```

### Проблема: Ошибка в API клиенте (Orval)

**Симптомы:**
- Типы API клиента не соответствуют реальному API
- Ошибка при генерации клиента

**Решение:**

1. Перегенерируйте API клиент:
```bash
npm run api:generate
```

2. Проверьте конфигурацию Orval:
```typescript
// orval.config.ts
import { defineConfig } from 'orval';

const inputTargerUrl = './mock/mock.api.json';

export default defineConfig({
  withToken: {
    input: { target: inputTargerUrl },
    output: {
      workspace: './src/shared/orval-api/withToken',
      target: './api',
      schemas: './types',
      client: 'react-query',
      httpClient: 'fetch',
    },
  },
});
```

3. Проверьте, что локальная OpenAPI спецификация валидна:
```bash
cat mock/mock.api.json
# опционально: проверка валидности JSON
node -e "JSON.parse(require('node:fs').readFileSync('mock/mock.api.json', 'utf8')); console.log('ok')"
```

## Mock режим

### Проблема: Mock данные не загружаются

**Симптомы:**
- Приложение делает запросы к API вместо mock данных
- `isLocalRun()` возвращает `false`

**Причина:**
Переменная `VITE_APP_ENV` не установлена в `local`

**Решение:**

1. Убедитесь, что `.env` содержит:
```bash
VITE_APP_ENV=local
```

2. Проверьте логику в `src/shared/lib/environment.ts`:
```typescript
const APP_ENV = import.meta.env.VITE_APP_ENV || 'local';

export const isLocalRun = () => APP_ENV === 'local';
```

3. Проверьте использование mock данных в коде:
```typescript
import { useQuery } from '@tanstack/react-query';
import { fetchWithToken } from '@/shared/lib/fetch-mutator';
import type { Space } from '@/entities/space/model/types';
import { isLocalRun } from '@/shared/lib/environment';
import { getMockSpaces } from '@/shared/mock/spaceMocks';

interface SpacesResponse {
  items: Space[];
}

interface SpacesResponseSuccess {
  data: SpacesResponse;
  status: number;
  headers: Headers;
}

export function useSpaces() {
  return useQuery<Space[]>({
    queryKey: ['spaces'],
    queryFn: async () => {
      if (isLocalRun()) {
        return getMockSpaces();
      }

      const { data } = await fetchWithToken<SpacesResponseSuccess>('/spaces');
      return data.items;
    },
  });
}
```

### Проблема: Mock данные не соответствуют реальному API

**Симптомы:**
- Типизация не совпадает
- Приложение падает при переключении на реальный API

**Решение:**

1. Проверьте типы mock данных:
```typescript
// src/shared/mock/spaceMocks.ts
import type { Space } from '@/entities/space/model/types';

export const mockSpaces: Space[] = [
  {
    id: '1',
    name: 'Mock Space',
    // ... другие поля
  },
];
```

2. Убедитесь, что типы соответствуют сгенерированному API клиенту:
```typescript
// src/entities/space/model/types.ts
export interface Space {
  id: string;
  name: string;
  // ... другие поля
}
```

## E2E тесты

### Проблема: E2E тесты падают с ошибкой

**Симптомы:**
- Тест падает с `Test timeout`
- Элемент не найден

**Причина:**
- Неправильные селекторы
- Ожидание не настроено
- Браузер не запущен

**Решение:**

1. Установите браузеры:
```bash
npx playwright install
```

2. Проверьте конфигурацию (`playwright.config.ts`):
```typescript
export default defineConfig({
  testDir: './e2e',
  webServer: {
    command: 'npm run dev',
    url: `http://localhost:${PORT}`,
    reuseExistingServer: !CI,
  },
  // ... остальная конфигурация
});
```

3. Проверьте селекторы в тесте:
```typescript
// e2e/auth-button.spec.ts
const authButton = page.getByRole('button', {
  name: /авторизация|login|войти/i,
});
await expect(authButton).toBeVisible();
```

### Проблема: TEST_SSO_APP_ID не определён

**Симптомы:**
- Тест падает с ошибкой `SSO_APP_ID environment variable is required`
- В `e2e/auth-button.spec.ts` читается `process.env.TEST_SSO_APP_ID`

Примечание: сообщение об ошибке содержит `SSO_APP_ID`, но фактически код читает `TEST_SSO_APP_ID`.

**Причина:**
Переменная окружения не определена для тестов

**Решение:**

В `.env` файле:
```bash
TEST_SSO_APP_ID=your-test-app-id
```

Или передайте через CLI:
```bash
TEST_SSO_APP_ID=your-test-app-id npm run tests:e2e
```

### Проблема: E2E тесты не видят элементы

**Симптомы:**
- `Error: Locator.click: Target closed`
- `Error: strict mode violation`

**Причина:**
- Элемент не отрендерился
- Несколько элементов с одинаковым селектором
- Таймаут слишком короткий

**Решение:**

1. Используйте ожидание:
```typescript
await expect(authButton).toBeVisible();
await authButton.click();
```

2. Увеличьте таймаут:
```typescript
test.beforeAll(() => {
  test.setTimeout(30_000);
});
```

3. Используйте более точные селекторы:
```typescript
// ❌ Плохо (несколько кнопок)
page.getByRole('button', { name: 'Button' })

// ✅ Хорошо (конкретная кнопка)
page.getByRole('button', { name: 'Создать пространство' })
```

## Сборка и деплой

### Проблема: Сборка падает с ошибкой TypeScript

**Симптомы:**
- Ошибка `TS2307: Cannot find module`
- Ошибка `TS2345: Type X is not assignable to type Y`

**Причина:**
- Ошибки типизации в коде
- Отсутствующие типы

**Решение:**

1. Проверьте типы:
```bash
npx tsc --noEmit
```

2. Исправьте ошибки типизации:
```typescript
// ❌ Неправильно
const space: any = data;

// ✅ Правильно
const space: Space = data;
```

3. Соберите проект:
```bash
npm run build
```

### Проблема: Vite билд медленный

**Симптомы:**
- Сборка занимает много времени
- Билд падает по таймауту

**Причина:**
- Много файлов
- Сложные зависимости
- Неоптимизированные импорты

**Решение:**

1. В текущем `vite.config.ts` нет блока `build`; при необходимости оптимизации можно добавить его, например так:
```typescript
// vite.config.ts
export default defineConfig({
  build: {
    sourcemap: true,
    rollupOptions: {
      output: {
        manualChunks: {
          'react-vendor': ['react', 'react-dom'],
          'tanstack-vendor': ['@tanstack/react-router', '@tanstack/react-query'],
        },
      },
    },
  },
});
```

2. Используйте Tree-shaking:
```typescript
// ❌ Неправильно (импортирует весь модуль)
import * as lucide from 'lucide-react';

// ✅ Правильно (импортирует только нужное)
import { IconName } from 'lucide-react';
```

### Проблема: Docker билд падает

**Симптомы:**
- Ошибка при сборке Docker образа
- Контейнер не запускается

**Причина:**
- Неправильный Dockerfile
- Отсутствующие зависимости
- Проблемы с портом

**Решение:**

Проверьте `Dockerfile` (в текущем проекте это минимальный dev-контейнер):
```dockerfile
FROM node:22-alpine

RUN apk add --update bash && rm -rf /var/cache/apk/*
WORKDIR /home/app

EXPOSE 5173

ENTRYPOINT /bin/bash
```

Если запускаете через docker compose в монорепозитории, проверьте порты:
```dockerfile
# В frontend Dockerfile
EXPOSE 5173

# В docker-compose.yaml
ports:
  - "3000:5173"
```
