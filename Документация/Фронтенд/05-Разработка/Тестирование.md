## Обзор тестирования

Проект использует два типа тестов:

| Тип | Инструмент | Назначение | Команда запуска |
|-----|----------|-----------|---------------|
| **Юнит тесты** | Vitest | Тестирование Zod схем и типобезопасности (сейчас в `entities/user`) | `npm run tests:unit` |
| **E2E тесты** | Playwright | Тестирование пользовательских сценариев в браузере | `npm run tests:e2e` |

## Юнит тестирование (Vitest)

### Запуск юнит тестов

```bash
# Запуск всех юнит тестов
npm run tests:unit

# Однократный запуск (без watch, удобно для CI/локальной проверки)
npm run tests:unit -- --run

# Запуск конкретного теста
npx vitest src/entities/user/model/__tests__/user.test.ts

# Запуск в режиме watch
npx vitest --watch
```

### Конфигурация Vitest

**Файл:** `vitest.config.ts`

```typescript
import { defineConfig } from 'vitest/config';

export default defineConfig({
  test: {
    include: ['src/**/*.{test,spec}.{js,mjs,cjs,ts,mts,cts,jsx,tsx}'],
    // exclude: ['src/ignored-folder/**'],
  },
});
```

**Параметры конфигурации:**
- `include` — шаблоны путей для поиска тестов (все файлы `.test.*` или `.spec.*` в папке `src/`)
- `exclude` — шаблоны путей для исключения из поиска тестов (по умолчанию отключено)

### Структура юнит тестов

Юнит тесты размещаются в папке `__tests__` рядом с тестируемым кодом:

```
src/
└── entities/
    └── user/
        └── model/
            ├── schema.ts
            ├── types.ts
            └── __tests__/
                └── user.test.ts
```

### Пример юнит теста (реальный код проекта)

**Файл:** `src/entities/user/model/schema.ts`

```typescript
import { z } from 'zod';

export const userDataSchema = z.object({
  username: z.string(),
  telegram_id: z.number(),
  first_name: z.string().optional(),
  last_name: z.string().optional(),
  photo_url: z.url().optional(),
  created_at: z.number(),
  permission: z.string().optional(),
});
```

**Файл:** `src/entities/user/model/types.ts`

```typescript
import { z } from 'zod';
import { userDataSchema } from './schema';

export type UserData = z.infer<typeof userDataSchema>;
```

**Файл:** `src/entities/user/model/__tests__/user.test.ts`

```typescript
import { describe, it, expect } from 'vitest';
import { userDataSchema } from '../schema';
import type { UserData } from '../types';

describe('User Schema Validation', () => {
  it('should validate a correct user object', () => {
    const name = 'ivan123';
    const validUser = {
      username: name,
      telegram_id: 12345678,
      first_name: 'Ivan',
      last_name: 'Ivanov',
      photo_url: 'https://ivanovich.com/photo.jpg',
      created_at: 1672531200,
      permission: 'admin',
    };

    const result = userDataSchema.safeParse(validUser);
    expect(result.success).toBe(true);

    if (result.success) {
      const userData: UserData = result.data;
      expect(userData.username).toBe(name);
    }
  });

  it('should validate a user with only required fields', () => {
    const minimalUser = {
      username: 'ivan123',
      telegram_id: 87654321,
      created_at: 1672531200,
    };

    const result = userDataSchema.parse(minimalUser);
    expect(result).toMatchObject(minimalUser);
  });

  it('should fail validation if required fields are missing', () => {
    const invalidUser = {
      username: 'Vasiliy',
      created_at: 1672531200,
    };

    const result = userDataSchema.safeParse(invalidUser);
    expect(result.success).toBe(false);

    if (!result.success) {
      expect(result.error.issues[0].path).toContain('telegram_id');
    }
  });

  it('should parse data and assign type', () => {
    const validUser = {
      username: 'ivan123',
      telegram_id: 12345,
      created_at: 1672531200,
    };
    const parsed = userDataSchema.parse(validUser);
    expect(parsed.username).toBe(validUser.username);
  });

  it('should fail validation with incorrect data types', () => {
    const invalidUser = {
      username: 'Vasiliy',
      telegram_id: 'not-a-number',
      created_at: 'now',
    };

    const result = userDataSchema.safeParse(invalidUser);
    expect(result.success).toBe(false);

    if (!result.success) {
      const paths = result.error.issues.map((i) => i.path[0]);
      expect(paths).toContain('telegram_id');
      expect(paths).toContain('created_at');
    }
  });

  it('should fail validation with invalid URL for photo_url', () => {
    const invalidUser = {
      username: 'Vasiliy',
      telegram_id: 12345,
      photo_url: 'not-a-url',
      created_at: 1672531200,
    };

    const result = userDataSchema.safeParse(invalidUser);
    expect(result.success).toBe(false);
  });

  it('demonstrates type inferred by zod schema', () => {
    const dataFromApi = {
      username: 'ivan123',
      telegram_id: 999,
      created_at: 123456789,
      extra_field: 'this is okay for partial matching but filtered out by zod',
    };

    const user: UserData = userDataSchema.parse(dataFromApi);
    // eslint-disable-next-line
    // @ts-ignore
    expect(user.extra_field).toBeUndefined();
    expect(user.username).toBe('ivan123');
  });
});
```

### Что тестируется в юнит тестах

В проекте юнит тесты используются для:

1. **Валидация Zod схем** — проверка правильности входных данных от API
2. **Проверка типов** — проверка корректности типизации TypeScript
3. **Позитивные сценарии** — проверка корректных данных
4. **Негативные сценарии** — проверка некорректных данных

### Шаблон юнит теста

```typescript
import { describe, it, expect } from 'vitest';
import { yourSchema } from '../schema';
import type { YourType } from '../types';

      // ... поля
    };

    expect(result.success).toBe(true);
  });

  it('should fail validation if required fields are missing', () => {
    const invalidObject = {
      // ... поля без обязательных
    };

    const result = yourSchema.safeParse(invalidObject);
    expect(result.success).toBe(false);
  });
});
```

## E2E тестирование (Playwright)

### Запуск E2E тестов

Скрипт `npm run tests:e2e` в `package.json` использует `node --env-file=.env`, поэтому переменные из `.env` автоматически подхватываются при запуске.

```bash
# Для auth E2E теста требуется TEST_SSO_APP_ID
export TEST_SSO_APP_ID=your-test-app-id

# Запуск всех E2E тестов
npm run tests:e2e

# Запуск конкретного теста (через project script с .env)
npm run tests:e2e -- e2e/auth-button.spec.ts

# Запуск в headed режиме (с открытым браузером, через project script)
npm run tests:e2e -- --headed

# Запуск с HTML-отчётом
npm run tests:e2e -- --reporter=html
npx playwright show-report
```

### Конфигурация Playwright

**Файл:** `playwright.config.ts`

```typescript
import { defineConfig, devices } from '@playwright/test';

const CI = !!process.env.CI;
const PORT = process.env.PORT || 5173;

export default defineConfig({
  testDir: './e2e',
  fullyParallel: true,
  forbidOnly: CI,
  retries: CI ? 2 : 0,
  workers: CI ? 1 : undefined,
  reporter: CI ? 'github' : 'list',
  use: {
    trace: 'on-first-retry',
  },

  /* Configure projects for major browsers */
  projects: [
    {
      name: 'chromium',
      use: { ...devices['Desktop Chrome'] },
    },
    {
      name: 'firefox',
      use: { ...devices['Desktop Firefox'] },
    },
    {
      name: 'webkit',
      use: { ...devices['Desktop Safari'] },
    },
  ],
  webServer: {
    command: 'npm run dev',
    url: `http://localhost:${PORT}`,
    reuseExistingServer: !CI,
  },
});
```

**Параметры конфигурации:**
- `testDir: './e2e'` — папка с E2E тестами
- `fullyParallel: true` — тесты запускаются параллельно
- `forbidOnly: CI` — в CI запрещено использовать `.only`
- `retries: CI ? 2 : 0` — в CI 2 попытки при ошибке
- `workers: CI ? 1 : undefined` — в CI один воркер
- `reporter: CI ? 'github' : 'list'` — формат отчёта
- `use: { trace: 'on-first-retry' }` — включается при первой повторной попытке
- `projects` — браузеры для тестирования (chromium, firefox, webkit)
- `webServer` — запуск dev сервера перед тестами

### Структура E2E тестов

E2E тесты размещаются в папке `e2e/`:

```
e2e/
├── auth-button.spec.ts
└── google_search.spec.ts
```

`google_search.spec.ts` — учебный пример Playwright и не покрывает бизнес-логику приложения.

### Пример E2E теста (реальный код проекта)

**Файл:** `e2e/auth-button.spec.ts`

```typescript
import { test, expect } from '@playwright/test';

const PORT = process.env.PORT || 5173;
const BASE_URL = process.env.E2E_BASE_URL || `http://training.wiki:${PORT}`;
const OAUTH_HOST = 'sso.oauth.name';

test.describe('Authorization button', () => {
  test('should redirect to sso.oauth.name with correct grant', async ({
    page,
  }) => {
    const applicationId = process.env.TEST_SSO_APP_ID;

    if (!applicationId) {
      throw new Error(
        'SSO_APP_ID environment variable is required for this test'
      );
    }

    // 1. Navigate to main page
    await page.goto(BASE_URL);

    // 2. Check authorization button exists
    const authButton = page.getByRole('button', {
      name: /авторизация|login|войти/i,
    });
    await expect(authButton).toBeVisible();

    // 3. Click authorization button
    await authButton.click();

    // 4. Verify redirect to sso.oauth.name with correct grant parameter
    await page.waitForURL((url) => url.hostname.includes(OAUTH_HOST));

    const currentUrl = new URL(page.url());
    expect(currentUrl.hostname).toContain(OAUTH_HOST);
    expect(currentUrl.searchParams.get('grant')).toBe(applicationId);
  });
});
```

Примечание: в текущем коде текст ошибки содержит `SSO_APP_ID`, хотя используется переменная `TEST_SSO_APP_ID`.

### Пример E2E теста с дополнительными проверками (реальный код проекта)

**Файл:** `e2e/google_search.spec.ts`

```typescript
import { test, expect } from '@playwright/test';

test.describe('Playwright introduction tests not related to project', () => {
  test.beforeAll(() => {
    test.setTimeout(30_000);
  });

  test('google search "who is larchanka"', async ({ page }) => {
    // Pass hl = host language parameter to ensure English UI
    await page.goto('https://www.google.com?hl=en');

    // Handle cookies
    const consentButton = page
      .getByRole('button', { name: /Reject all|Accept all/i })
      .first();
    if (await consentButton.isVisible({ timeout: 2000 })) {
      await consentButton.click();
    }

    // Search textarea or input with name="q"
    const searchInput = page
      .locator('textarea[name="q"]')
      .or(page.locator('input[name="q"]'));
    await expect(searchInput).toBeVisible();
    await searchInput.click();
    await searchInput.fill('who is larchanka');
    await searchInput.press('Enter');

    // Check new page title
    await expect(page).toHaveTitle(/larchanka/);

    // Check if new page is captcha / restriction policy
    if (
      (await page.getByText('Unusual traffic').isVisible()) ||
      (await page.locator('#captcha').isVisible())
    ) {
      console.warn(
        'Warning: Google returned a CAPTCHA or "Unusual traffic" page.'
      );
      return;
    }

    // Search globally for the link
    const linkedinLink = page.locator('a[href*="linkedin.com"]');
    await linkedinLink.first().waitFor({ state: 'attached', timeout: 5000 });
    const count = await linkedinLink.count();
    if (count === 0) {
      console.warn('Warning: No LinkedIn links found for "who is larchanka"');
    } else {
      expect(count).toBeGreaterThan(0);
    }
  });
});
```

### Что тестируется в E2E тестах

В проекте E2E тесты используются для:

1. **Проверка авторизации** — редирект на SSO, параметры запроса
2. **Базовая проверка окружения Playwright** — демонстрационный тест на внешнем сайте (`google_search.spec.ts`)
3. **Расширяемый каркас** — место для добавления проверок UI и навигации самого приложения

### Основные методы Playwright

| Метод | Назначение |
|-------|-----------|
| `page.goto(url)` | Переход по URL |
| `page.getByRole(role, options)` | Поиск элемента по роли |
| `page.locator(selector)` | Поиск элемента по селектору |
| `element.click()` | Клик по элементу |
| `element.fill(text)` | Заполнение текстового поля |
| `element.press(key)` | Нажатие клавиши |
| `expect(element).toBeVisible()` | Проверка видимости |
| `expect(page).toHaveTitle(pattern)` | Проверка заголовка страницы |
| `page.waitForURL(predicate)` | Ожидание изменения URL |
| `element.isVisible()` | Проверка видимости элемента |

### Шаблон E2E теста

```typescript
import { test, expect } from '@playwright/test';

test.describe('Feature name', () => {
  test('should do something', async ({ page }) => {
    // 1. Navigate to page
    await page.goto(BASE_URL);

    // 2. Check element exists
    const button = page.getByRole('button', { name: 'Button' });
    await expect(button).toBeVisible();

    // 3. Interact with element
    await button.click();

    // 4. Verify result
    await expect(page).toHaveURL(/expected-url/);
  });
});
```

## Конфигурация

### package.json скрипты

**Файл:** `package.json`

```json
{
  "scripts": {
    "tests:unit": "vitest",
    "tests:e2e": "node --env-file=.env node_modules/@playwright/test/cli.js test"
  }
}
```

### Переменные окружения

Для E2E тестов используются следующие переменные окружения:

| Переменная | Назначение | По умолчанию |
|----------|-----------|-------------|
| `PORT` | Порт dev сервера | `5173` |
| `E2E_BASE_URL` | Базовый URL для тестов | `http://training.wiki:${PORT}` |
| `TEST_SSO_APP_ID` | ID SSO приложения для тестов | (требуется) |
| `CI` | Флаг CI окружения | (автоматически) |
