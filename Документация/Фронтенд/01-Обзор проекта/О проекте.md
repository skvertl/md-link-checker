## Общее описание

Python-TypeScript Wiki Frontend — это SPA для работы с пространствами знаний, построенное на React 19 + TypeScript. Текущая версия фронтенда включает авторизацию через внешний SSO-провайдер (`sso.oauth.name`), дашборд пространств, просмотр пространства и его статей, а также UI для управления участниками пространства.

### Основные возможности

- **Пространства (Spaces)** — Организация знаний в изолированные рабочие области
- **Создание пространства** — Модальное окно создания из header
- **Управление статьями** — Просмотр списка статей внутри пространства
- **Редактор и иерархия статей** — В планах, пока не реализованы в текущем коде
- **Коллаборация** — Управление пользователями и ролями в пространствах (в текущей реализации `features/edit-space` работает через mock-слой)
- **SSO OAuth** — Авторизация через внешнего провайдера и создание сессии
- **Type-safe API** — Генерация API-клиента из OpenAPI спецификации (Orval)

## Цели проекта

### Функциональные цели
1. **Централизованное управление знаниями** — Единое место для хранения документации
2. **Командная работа** — Совместное редактирование с контролем доступа
3. **Быстрый доступ к информации** — Поиск и навигация по структурированному контенту

### Технические цели
1. **Масштабируемая архитектура** — FSD подход для роста команды
2. **Type Safety** — Типизированные доменные модели и API-контракты (TypeScript + Zod для схем контрактов и тестовой валидации; runtime-валидация API-ответов в UI пока не подключена)
3. **Developer Experience** — Mock API, hot reload, автоматическая генерация кода
4. **Современный стек** — React 19, TanStack Query, Tailwind CSS

## Ключевые особенности архитектуры

### Feature-Sliced Design (FSD)

Проект следует методологии **Feature-Sliced Design** — современному подходу к организации фронтенд-кода с чётким разделением ответственности:

```
app → pages → (widgets / features / entities) → shared
```

**Преимущества FSD:**
- Ясные границы модулей
- Контролируемые зависимости (зависимости только сверху вниз)
- Масштабируемость для команд любого размера
- Простота тестирования каждого слоя

**Текущее исключение проекта:** в `shared/mock` есть импорты из `entities` (type-only импорты и runtime-константа `userRoles` в `shared/mock/users.ts`).

### API-клиент и слой данных

- **Orval** — Генерация TypeScript-клиента из OpenAPI спецификации
- **TanStack Query** — Автоматическое управление кэшем и состоянием
- **Zod** — Схемы контрактов (доменная схема `entities/user/model/schema.ts` и сгенерированные `*.zod.ts`)

### Два режима работы

| Режим | Описание | Переменная |
|-------|----------|------------|
| **Local (Mock)** | Чтение пространств и деталей пространства идёт из моков (`useSpaces`, `useSpace`); `features/edit-space` также использует mock-API; создание пространства остаётся API-зависимым | `VITE_APP_ENV=local` |
| **Real API** | `useSpaces`/`useSpace` читают данные с бэкенда; создание пространства работает через API; лента активности (`mockActivities`) и `features/edit-space` в текущей реализации остаются на моках | любое значение `VITE_APP_ENV`, кроме `local` (например `development`) |

## Пользовательские сценарии

### 1. Авторизация через SSO

```
Пользователь → Нажимает "Авторизация"
→ Редирект на sso.oauth.name
→ Возврат в приложение с query-параметром token
→ Проверка токена (/token) → Создание сессии
→ Редирект на сохранённый URL или /home
```

### 2. Работа с пространствами

```
Дашборд → Просмотр списка пространств → Открытие пространства
→ (через настройки) изменение названия и состава участников (mock-поток)
→ (через header) создание нового пространства
```

### 3. Редактирование контента

```
Пространство → Просмотр списка статей
→ Редактирование статьи *(в планах)*
```

## Требования безопасности

- **SSO OAuth** — Интеграция с внешним SSO-провайдером (`sso.oauth.name`)
- **Session токены** — Opaque токены с ограниченным сроком действия (контролируется бэкендом; срок проверяется на фронтенде в `auth-utils`)
- **CORS контроль** — Настраивается на уровне бэкенда
- **Роли доступа** — Admin, Writer, Reader в UI управления участниками пространства
- **Bypass для dev-режима** — Возможность отключить `requireAuth` на защищённых роутах через `VITE_BYPASS_AUTH=true` (редирект с корневого `/` по-прежнему определяется проверкой `isAuthenticated()`)

## Ограничения

| Аспект | Ограничение |
|--------|-------------|
| **Браузеры** | Современные браузеры (ES2022+) |
| **Авторизация** | Для полного auth-потока нужны доступ к SSO-провайдеру и корректный `VITE_SSO_APP_ID` (в dev можно временно включить `VITE_BYPASS_AUTH=true`) |
| **Offline** | Нет полной offline-поддержки (только mock режим) |
| **Мобильная версия** | Адаптивный дизайн, но не PWA |
| **Полнота CRUD** | `features/edit-space` в текущей реализации работает через mock-данные, а не через backend API |

1. **Feature branches** — Все изменения в отдельных ветках
