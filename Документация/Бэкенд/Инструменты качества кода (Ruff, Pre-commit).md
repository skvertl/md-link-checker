<a name="бизнес-ценность"></a>
### 🎯 Бизнес-ценность

Внедрение Ruff и pre-commit hooks направлено на повышение стабильности продукта и ускорение процесса разработки:
*   **Снижение затрат на Code Review**: Автоматизация проверок стиля кода позволяет разработчикам фокусироваться на логике приложения, а не на синтаксических нюансах.
*   **Единый стандарт качества**: Весь код в репозитории приводится к общему виду, что упрощает онбординг новых сотрудников и поддержку проекта.
*   **Предотвращение ошибок на раннем этапе**: Автоматические проверки блокируют попадание «битого» кода (невалидный JSON/YAML, конфликты слияния) в общую ветку.
*   **Высокая скорость работы**: Ruff работает в десятки раз быстрее классических линтеров (pylint, flake8), что экономит время разработчиков и ресурсы CI/CD.

<a name="техническая-реализация"></a>
### ⚙️ Техническая реализация

Система состоит из двух компонентов: линтера **Ruff** (анализ и форматирование) и менеджера хуков **Pre-commit** (запуск проверок перед созданием коммита).

#### Конфигурация Pre-commit Hooks
В файле `.pre-commit-config.yaml` настроены следующие проверки:

| ID хука | Репозиторий | Описание | Обязателен |
| :--- | :--- | :--- | :--- |
| `check-merge-conflict` | pre-commit-hooks | Поиск строковых маркеров конфликтов слияния | Да |
| `trailing-whitespace` | pre-commit-hooks | Удаление лишних пробелов в конце строк | Да |
| `end-of-file-fixer` | pre-commit-hooks | Гарантирует наличие пустой строки в конце файла | Да |
| `check-yaml` / `json` | pre-commit-hooks | Проверка валидности синтаксиса конфигурационных файлов | Да |
| `ruff-check` | ruff-pre-commit | Статический анализ Python-кода и автоисправление (`--fix`) | Да |
| `ruff-format` | ruff-pre-commit | Автоматическое форматирование Python-кода | Да |

#### Основные параметры Ruff
Настройки линтера определены в `pyproject.toml`. Ключевые параметры:
*   **Длина строки**: 120 символов.
*   **Набор правил**: `ALL` (включая проверку импортов и форматирование).

<a name="установка-и-настройка"></a>
### 📦 Установка и настройка

Для активации инструментов в локальной среде разработки выполните следующие команды:

bash
# 1. Установка зависимостей
pip install -r requirements.txt

# 2. Инициализация хуков в локальном .git
pre-commit install


<a name="работа-с-инструментами"></a>
### 🚀 Работа с инструментами

#### Ручной запуск проверок
Вы можете запустить проверку кода в любой момент, не дожидаясь коммита:

bash
# Проверить все файлы проекта
pre-commit run --all-files

# Запустить только ruff для конкретного файла
ruff check app/main.py --fix


#### Использование Ruff CLI
Команды для управления качеством кода:

| Команда | Описание |
| :--- | :--- |
| `ruff check .` | Проверить текущую директорию на ошибки |
| `ruff check . --fix` | Найти и автоматически исправить доступные ошибки |
| `ruff format .` | Отформатировать код согласно стандартам проекта |

<a name="важно"></a>
### ⚠️ Важно

> **Блокировка коммита**: Если pre-commit hook обнаружит ошибку, которую не может исправить автоматически, создание коммита будет прервано. Вам необходимо исправить замечания и повторно выполнить `git add`.

> **Исключения**: В файле `.pre-commit-config.yaml` настроено исключение для директории `.idea/` и файла `docs/cli_help.md`. Не добавляйте в эти пути критически важный код, требующий проверки.

> **Обход проверок**: В исключительных случаях (экстренные правки) проверки можно пропустить командой `git commit --no-verify`, однако это крайне не рекомендуется правилами разработки нашей компании.
