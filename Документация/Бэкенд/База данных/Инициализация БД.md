# Инициализация базы данных (локально)

Документ описывает базовые шаги для запуска и проверки PostgreSQL + pgAdmin и применения миграций в локальном Docker-окружении.

## Шаг 1 — поднять сервисы

В корне проекта (где `docker-compose.yml`) выполните:

```
chmod +x start-services.sh
./start-services.sh
```

Или напрямую:

```
docker compose up -d
```

Подождите несколько секунд — контейнеры инициализируются.

## Шаг 2 — проверить состояние БД

- Просмотреть контейнеры: `docker ps`
- Логи Postgres: `docker compose logs -f postgres`

Подключитесь к базе через `psql` (если установлен локально) или внутри контейнера:

```
docker compose exec postgres psql -U $POSTGRES_USER -d $POSTGRES_DB
```

## Шаг 3 — применить миграции

```
docker compose exec api alembic upgrade head
```

Проверьте наличие таблицы `alembic_version` и ожидаемых таблиц (`
\dt` в psql).

## Шаг 4 — подключиться через pgAdmin

Откройте `http://localhost:5050` (или `pgadmin.training.wiki` при настройке hosts), используйте `PGADMIN_DEFAULT_EMAIL` и `PGADMIN_DEFAULT_PASSWORD`.

- Databases → wiki → Schemas → public → Tables

## Проверка корректности

- Таблица `alembic_version` должна существовать.
- Если миграции не применяются — проверьте `alembic.ini`, переменные окружения и логи контейнера API.

## Полезные команды

- Список таблиц: `
\dt
`
- Информация о таблице: `\d <table_name>`
- Вручную применить SQL-скрипт: `psql -f file.sql`
