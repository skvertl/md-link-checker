# Переменные окружения для работы с базой данных

Краткое описание

Этот документ объясняет, какие переменные окружения нужны для локальной разработки, Docker и CI, где хранить секреты и как организовать per-service `.env` в репозитории с субмодулями. 

## Кратко

Команда хранит секреты в **GitHub Secrets** (В настройках GitHub-репозитория: Settings > Secrets and variables > Actions). В репозитории должны быть только шаблоны `*.env.example` (по одному в корне или в каждом субмодуле). Для локальной разработки создавайте per-service `.env` (например, `frontend/.env`, `api/.env`) и добавляйте их в `.gitignore`.

## Основные переменные

Коротко про переменные, которые чаще всего нужны для работы с базой данных:

- `POSTGRES_USER` — имя пользователя для Postgres
- `POSTGRES_PASSWORD` — пароль для пользователя
- `POSTGRES_DB` — имя базы данных
- `POSTGRES_HOST` — хост (в Docker обычно `postgres`)
- `POSTGRES_PORT` — порт (обычно `5432`)
- `DATABASE_URL` — строка подключения в виде `postgresql+psycopg://user:pass@host:port/db`

Дополнительно (pgAdmin): `PGADMIN_DEFAULT_EMAIL`, `PGADMIN_DEFAULT_PASSWORD`.

## Где хранить и как организовать `.env`

- Root `.env.example` — общий шаблон для `docker-compose`.
- В каждом субмодуле (например, `frontend/`, `api/`) держите свой `*.env.example` и локальный `*.env` (не коммитить).
- Для локальной работы скопируйте `*.env.example` → `*.env` и заполните значения.

## CI — GitHub Secrets

- Секреты хранятся в Settings → Secrets and variables → Actions.
- В GitHub Actions используйте `secrets.NAME` и не кладите реальные пароли в репозиторий.

## Пример (коротко)

Скопировать шаблон и заполнить локально:

cp .env.example .env

Пример `*.env.example` (placeholders):

POSTGRES_USER=admin
POSTGRES_PASSWORD=changeme
POSTGRES_DB=wiki
POSTGRES_HOST=postgres
POSTGRES_PORT=5432
DATABASE_URL=postgresql+psycopg://admin:changeme@postgres:5432/wiki

## Практики безопасности

- Не храните секреты в VCS. Используйте GitHub Secrets для CI и production.
- Даёте приложению минимально необходимые права на БД.
- Документируйте процесс смены/ротации паролей.

## Быстрая проверка при проблемах

1. Убедитесь, что соответствующий `*.env` создан и заполнен.
2. Проверьте полные переменные в GitHub Secrets для CI.
3. Посмотрите логи контейнеров: `docker compose logs`.
4. Попробуйте подключиться к БД вручную через psql.
