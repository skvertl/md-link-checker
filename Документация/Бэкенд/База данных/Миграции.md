## Что сделано в проекте

- Подключены зависимости для работы с БД и миграциями: SQLAlchemy, Alembic, psycopg[binary], asyncpg.
- Alembic инициализирован и связан с `app.models.Base`; URL берётся из `DATABASE_URL` и автоматически приводит драйвер к `postgresql+psycopg`.
- Созданы миграции:
  - `0001_create_tmp_table` — вспомогательная таблица `tmp`.
  - `0002_create_users_table` — таблица `users` с `telegram_id` (unique) и полями профиля.
  - `0003_add_last_login_at` — добавлен `last_login_at`, `username` стал nullable.
  - `0004_create_sessions_table` — таблица `sessions` с хранением `token_hash` и TTL.
- В `docker-compose.yml` сервис `api` выполняет `alembic upgrade head` перед запуском FastAPI; сервис `db` поднимает PostgreSQL 16 (`wiki` на `localhost:5433`).

## Используемые инструменты

### PostgreSQL
Основная БД, поднимается через `docker compose` (пользователь `admin`, пароль `admin123`, БД `wiki`, порт хоста `5433`).

### SQLAlchemy
Модели определены в `app/models.py` и используются как источник `Base.metadata` для Alembic (даже при том, что runtime-репозитории работают на asyncpg).

### Alembic
Отвечает за:
- создание миграций;
- применение изменений схемы БД;
- хранение текущей версии схемы в таблице `alembic_version`.

## Конфигурация Alembic

### env.py

- Берёт URL из `DATABASE_URL` или `alembic.ini` и приводит драйвер к `postgresql+psycopg` (если пришёл как `postgresql://...`).
- Использует `Base.metadata` из `app.models`.
- Работает в online/offline режимах, подключения создаются через `NullPool`.
- Для автогенерации моделей важно, чтобы новые модели были импортированы в `app/models.py`, иначе Alembic их не «увидит».

### script.py.mako

- Стандартный шаблон ревизий с `upgrade`/`downgrade`, без дополнительных хуков.

## Порядок миграций и схемы

### 0001_create_tmp_table

- Тестовая таблица `tmp` с `id SERIAL PRIMARY KEY` для проверки контура миграций.

### Таблица users

- Ревизии: `0002_create_users_table`, `0003_add_last_login_at`.
- Поля:
  - `id` — integer, PK.
  - `telegram_id` — bigint, NOT NULL, UNIQUE (`uq_users_telegram_id`).
  - `username` — varchar(255), nullable (с `0003`).
  - `first_name`, `last_name` — varchar(255), nullable.
  - `photo_url` — varchar(1024), nullable.
  - `permission` — varchar(64), nullable.
  - `created_at`, `updated_at` — timestamptz, `server_default=now()`.
  - `last_login_at` — timestamptz, `server_default=now()`, NOT NULL.
- Используется для upsert по `telegram_id` при верификации токена `/token`.

### Таблица sessions

- Ревизия: `0004_create_sessions_table`.
- Поля:
  - `id` — UUID, PK.
  - `user_id` — bigint, FK → `users.id`, index `ix_sessions_user_id`.
  - `token_hash` — varchar(64), UNIQUE (sha256 от session token, raw значение не хранится).
  - `expires_at` — timestamptz, NOT NULL, index `ix_sessions_expires_at`.
  - `revoked_at` — timestamptz, nullable, index `ix_sessions_revoked_at`.
  - `created_at`, `updated_at` — timestamptz, `server_default=now()`.
- Используется для stateful-сессий `/session` (TTL + отзыв).

## Команды Alembic

### Локально

- Активировать виртуальное окружение и задать URL БД, если контейнеры подняты по умолчанию:

```bash
export DATABASE_URL=postgresql://admin:admin123@localhost:5433/wiki
```

- Создать ревизию (автогенерация):

```bash
alembic revision --autogenerate -m "message"
```

- Применить/откатить:

```bash
alembic upgrade head
alembic downgrade -1
```

- Диагностика:

```bash
alembic current
alembic history
```

### В Docker

- Поднять сервисы (миграции в `api` применятся автоматически перед запуском приложения):

```bash
docker compose up -d
```

- Применить миграции после создания новой ревизии:

```bash
docker compose exec api alembic upgrade head
```

- Создать ревизию внутри контейнера (если нужна автогенерация):

```bash
docker compose exec api alembic revision --autogenerate -m "message"
```

## Идемпотентность и upsert

- Уникальность `telegram_id` обязательна для корректной работы `INSERT ... ON CONFLICT`.
- `last_login_at` обновляется при каждом успешном verify, `created_at` задаётся только при создании.
- `token_hash` уникален, индексы по `user_id`/`expires_at`/`revoked_at` ускоряют проверки TTL и поиска активных сессий.

## Безопасные практики при миграциях

- Перед деструктивными изменениями (drop/alter type) делайте резервную копию БД.
- Новые колонки добавляйте nullable, делайте backfill, затем ставьте `NOT NULL` (двухшагово, чтобы не уронить прод).
- Для больших таблиц используйте `CREATE INDEX CONCURRENTLY` (разбивайте миграцию на отдельные `up/down` без транзакции по умолчанию).
- Всегда проверяйте автогенерацию: Alembic может не увидеть модель, если она не импортирована в `app/models.py`.
- После создания ревизии просмотрите `upgrade`/`downgrade`, особенно для изменений типов/дефолтов.

## Проверка работы миграций

- `docker compose up -d` (при старте `api` уже вызывает `alembic upgrade head`).
- Проверить версию миграций:

```bash
docker compose exec api alembic current
```

- Убедиться, что таблицы есть в БД:

```bash
docker compose exec db psql -U admin -d wiki -c '\dt'
docker compose exec db psql -U admin -d wiki -c 'select * from alembic_version;'
```

- При необходимости посмотреть схему/индексы:

```bash
docker compose exec db psql -U admin -d wiki -c '\\d+ users'
docker compose exec db psql -U admin -d wiki -c '\\d+ sessions'
```

## CI-проверка

Пример джоба, который прогоняет миграции на тестовой БД PostgreSQL в GitHub Actions:

```yaml
name: DB Migrations Check
on: [push, pull_request]
jobs:
  migrations:
    runs-on: ubuntu-latest
    services:
      postgres:
        image: postgres:16
        env:
          POSTGRES_USER: admin
          POSTGRES_PASSWORD: admin123
          POSTGRES_DB: wiki
        ports:
          - 5432:5432
        options: >-
          --health-cmd "pg_isready -U admin -d wiki"
          --health-interval 5s
          --health-timeout 5s
          --health-retries 10
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.11"
      - name: Install dependencies
        run: pip install -r requirements.txt
      - name: Alembic upgrade (test DB)
        env:
          DATABASE_URL: postgresql://admin:admin123@localhost:5432/wiki
        run: |
          alembic upgrade head
          alembic current
```

## Ожидаемый результат

После `alembic upgrade head` в БД `wiki` должны быть:

- таблицы `tmp`, `users`, `sessions`;
- `users.telegram_id` уникален, `sessions.token_hash` уникален, индексы на `sessions(user_id, expires_at, revoked_at)`;
- запись в `alembic_version` с `0004_create_sessions_table` (текущий head).

Это подтверждает корректную настройку Alembic и готовность базы к дальнейшему развитию.
